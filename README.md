## How it is built

Plain HTML, CSS and JavaScript — no framework, no build toolchain, no tracking.
The four pages are generated by `build.py`, which holds all copy in one place so
the markup stays consistent:

```bash
python build.py           # requires Pillow, used only to read image orientation
python deploy.py --build  # rebuild, stage the public files, push to Cloudflare Pages
```

`deploy.py` stages only the published files into `.deploy/` first, so `build.py`,
this README and the git directory never reach the CDN. Cloudflare serves clean
paths (`/about`, not `/about.html`) and 308-redirects the `.html` form, which is
why canonical links and the sitemap use the extensionless URLs while the in-page
links keep `.html` — that way the GitHub Pages mirror keeps working too.

Content lives in three structures inside `build.py`: `PROJECTS` (shipped work),
`PROTOTYPES` (the lab, ordered by `_PROTO_ORDER`) and `LIFE` (the about page).

## Contact form

The contact dialog posts to [FormSubmit](https://formsubmit.co) via `fetch`, which
relays the message to the inbox. **The address has to be activated once** — the
first submission triggers a confirmation email; click the link in it and every
later message arrives normally. If the request fails for any reason the form falls
back to a prefilled `mailto:` link, so a visitor never loses what they typed.

To swap the address for FormSubmit's hashed endpoint later, change the `action`
in `build.py`'s `footer()`.
